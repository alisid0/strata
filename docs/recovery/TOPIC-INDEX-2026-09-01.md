# Qubix University — comprehensive topic index

Audit date: 1 September 2026  
Primary source: [qubix.university](https://qubix.university/)  
Coverage basis: all 134 URLs in the site’s published [sitemap](https://qubix.university/sitemap.xml), including the 17-phase wiki, 35 reading sessions, 21 core missions, library, mathematics pilot, Superstore rooms/data world, showcase, glossary pages, and role-game/planning pages.

## Executive summary

Qubix University is a shop-floor-themed data-science learning environment built around a fictional retail company, Qubix Superstore. Its public content spans:

- **379 explicitly named curriculum topics** across 17 wiki phases.
- **35 published reading sessions** across eight sitemap-visible chapters.
- **21 practical investigations** in the core Superstore mission route.
- **24 published glossary terms**.
- **10 mathematics-pilot subtopics**.
- **Four library works**, including a substantial functions-to-calculus book and a graph atlas.
- **Six relational data domains**, 10 named Superstore tables in the world overview, and a broader career/role ladder.
- Four planned post-foundation volumes: Analyst, Data Engineer, Data Scientist, and Machine Learning Engineer.

Important site inconsistency: the homepage describes seven chapters and 35 sessions, but the sitemap exposes an additional four-session **Chapter 8, Chance and Inference**. The 35-session total already includes that chapter; the homepage’s chapter count and chapter navigation appear stale.

## 2. Published foundation reading course — 35 sessions

### Chapter 1 — How Data Represents the World (5)

1. **A sale is not its record** — events versus records; goods versus data; rows as partial evidence; observed, stored/lookup, calculated/derived values; origins and failure points of checkout values.
2. **Rows and columns** — what a row represents; what a column contains across rows; reading tables.
3. **What one row represents** — grain; the same purchase recorded at different grains; naming the row before counting.
4. **Zero, blank or missing?** — zero versus unknown; pending values; not applicable; using process evidence to interpret blanks.
5. **From a request to an analysis** — purpose, question, boundary, evidence limits, analytical outcome, defensible briefs.

### Chapter 2 — Numbers, Ratios and Change (4)

1. **Four what? Every number needs a unit** — units; dimensional meaning; why 0 kg differs from 0 °C; conversion while retaining original values.
2. **Two branches both report 12%, how are they still different?** — ratios, percentages, rates, denominators, sample size and fair comparison.
3. **Absolute change, relative change and rate of change** — differences, starting values, percentage change, time/unit denominators, asymmetric percentage rises and falls.
4. **From table to rule to graph** — variables, quantities, algebraic rules, functions, graphs, intercepts and fixed components.

### Chapter 3 — Data Quality and Evidence (4)

1. **A blank cell does not mean zero** — missing-data effects on calculations; types/reasons for absence; diagnosing blanks from process evidence.
2. **A postcode and a price can both contain numbers. Why treat them differently?** — categorical versus quantitative values; identifiers; ordinal data; measurement scales; invalid arithmetic on labels/categories.
3. **Does one row mean one sale or one product?** — grain, keys, composite uniqueness, snapshots, true versus apparent duplicates.
4. **Where did this number come from?** — provenance, source records, transformations, lineage, preserving raw values, uncertainty.

### Chapter 4 — Statistics Before Models (6)

1. **From raw values to a distribution** — frequency, relative frequency, cumulative frequency and empirical distributions.
2. **Look at the shape before the summary** — distributions, histogram bins, multimodality, and information lost through summary statistics.
3. **Centre is a choice** — mean, median, mode, skewness and decision-appropriate measures of centre.
4. **Measuring spread** — range, quartiles, IQR, variance, standard deviation and five-number summaries.
5. **Who is in the data, and who is not** — population, sample, sampling frame, selection bias, variation versus error and claim boundaries.
6. **The language of chance** — events, probability direction, conditional probability, independence and base-rate reasoning.

### Chapter 5 — SQL Foundations (4)

1. **Asking a table a question** — SELECT, WHERE, ORDER BY, row/column selection, NULL and SQL’s third truth value.
2. **Grouping changes the grain on purpose** — GROUP BY, pre/post-aggregation filtering, counting, HAVING and summary grain.
3. **Joining without changing what a row is** — matching rules, join survival, one-to-many expansion, price history and count checks.
4. **Checking a result before believing it** — result grain, boundaries, control totals, NULL behaviour, query retention and release checks.

### Chapter 6 — Python Foundations (4)

1. **Values, names and types** — scalar types, assignment/names, type-dependent operations and text-versus-number errors.
2. **Decisions and repetition** — conditions, loops, accumulation, variable state and execution tracing.
3. **Giving a piece of work a name** — functions, inputs, outputs, testing and bad-input/None behaviour.
4. **Collections, and a table in code** — lists, mappings, tabular transformations, file ingestion, CSV typing and schema checks.

### Chapter 7 — Explain What You Found (4)

1. **A table someone can actually read** — explicit row grain, visible absence, notes and one-purpose tables.
2. **A chart that does not flatter** — question-driven chart selection, axes, scales, labels, accessibility and misleading truncation.
3. **Separating what you found from what you think** — observation, interpretation and recommendation; correlation versus causation; limits and confounding.
4. **Work somebody else can run** — reproducibility, provenance, inputs, versions, commands, checks, hand-edited spreadsheets and responsible data handling.

### Chapter 8 — Chance and Inference (4; sitemap-visible but omitted from homepage chapter navigation)

1. **A probability is a proportion of something named** — named events, denominators, context-specific probabilities and independence.
2. **What you already know changes the number** — conditioning, restricted denominators, base rates and alarm accuracy.
3. **What a sample can and cannot say** — estimators, sampling variation, sample size, confidence intervals and uncertainty around elasticity estimates.
4. **Different, or different this week?** — null hypotheses, p-values, effect size, practical versus statistical significance and large-sample traps.

## 3. The 21 core Superstore missions

1. **Process a Sale** — identify whether checkout values were observed, looked up or derived.
2. **Read the Table** — identify row contents and column meaning.
3. **What Does One Row Represent?** — state grain precisely enough to count.
4. **Missing Values Are Not Zero** — interpret five forms of empty cell.
5. **Units and Measurement** — identify what a value measures and convert without discarding the original.
6. **SUM(quantity)** — verify that an aggregated column has one meaning and confirm totals by a second route.
7. **The Rate Desk** — name the denominator beneath a figure before comparison.
8. **Classify Store Data** — classify value types and permissible operations.
9. **Keys and Duplicate Records** — determine uniqueness and distinguish real duplicates.
10. **Trace the Number** — reconstruct origin and transformations of a reported figure.
11. **The Distribution Desk** — inspect distribution shape before selecting a summary.
12. **What Does It Cost?** — set price grain and calculate a question-appropriate weighted average.
13. **The Sampling Desk** — define population boundaries from the sampling frame.
14. **The SQL Console** — build a query clause by clause and monitor grain.
15. **The Region That Wasn’t** — validate grouping-column hierarchies before regional reporting.
16. **Join Without Changing the Grain** — predict and test the effect of a join on rows.
17. **The Result Checkpoint** — test grain, boundaries, NULL behaviour and control totals before release.
18. **Read the Program** — trace Python names/state and compare predicted with actual execution.
19. **The Chart Clinic** — choose a chart, then audit scale, labels and accessibility.
20. **Analyst Decision Desk** — turn an unclear question into a unit, evidence, chart and defensible claim.
21. **The Handover Pack** — package inputs, versions, commands and checks for reproducibility.

Campaign/story-mode labels also mention: **Classify Store Data, What Is Missing?, What Does One Row Represent?, Keys and Duplicate Records, Units and Measurement, Trace the Number**, and the morning-report problem of **seven systems feeding one report**.

## 11. Overall conceptual map

The site’s full subject arc is:

**digital literacy → enterprise/data orientation → mathematical foundations → data literacy and quality → descriptive statistics and visualisation → probability → sampling and inference → SQL → Python → business intelligence → analytics engineering → data engineering → ML mathematics → machine learning → forecasting/optimisation/causal work → deep learning/AI/production ML → technical and organisational data leadership.**

Across those stages, recurring ideas are grain, units, denominators, provenance, uncertainty, reproducibility, validation, responsible communication and the limits of what evidence can support.

## 12. Scope notes

- “Topic” was treated as every explicitly named curriculum item, session title, lesson heading cluster, mission title/description, glossary entry, library chapter/section, pilot subtopic, named data domain/table, role/career title and showcase/tool theme.
- Routine interface labels, navigation words, XP values, timestamps, button text, legal boilerplate and repeated footer wording were excluded because they are not substantive subject matter.
- The site describes its work as AI drafts under founder review; topic names and availability may change.
